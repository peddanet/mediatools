### `CodecCache` (`mediatools.core.codeccache`) {.unnumbered}

~~~text
Remembers the video codec of files keyed by path, size and mtime.

The shrink plan asks for the codec of every candidate, so that videos
which are already HEVC can be reported (and left out of volume and time
estimates) before the start question. Probing costs one ffprobe process
per file; the cache answers repeated plans almost instantly. An entry is
used only while size and modification time are unchanged, so a file
that was shrunk in place is probed again. Storage and lookup are those
of :class:`DurationCache`; only the value is a codec name.

Stored as TSV ``path<TAB>size<TAB>mtime_ns<TAB>codec``.
~~~

### `DecodeCheck` (`mediatools.core.decodecheck`) {.unnumbered}

~~~text
Decodes the start of a video and counts the decoder errors.

Some videos have an intact container (``ftyp``/``mdat``/``moov``,
plausible duration, codec ``avc1``) but sample data a decoder cannot
use: still encrypted after the encryption boxes were stripped, or
scrambled. Encoding such a file takes as long as a good one and yields a
grey or empty result. A short trial decode finds them in seconds: a
healthy video decodes without errors, an unusable one produces errors
from the first frame on (``decode_slice_header error``, ``no frame!``,
``non-existing PPS``, AAC ``channel element ... is not allocated``).

:meth:`verify` decodes a whole file and accepts it only without a
single error; ``shrink`` uses it on every encoded output before the
original is replaced.

The check reads only; it never writes or changes the file.

Attributes:
    ffmpeg: Name or path of the ffmpeg executable.
    seconds: Length of the trial decode from the start, in seconds.
    max_errors: A file with at least this many error lines is unusable.
    timeout: Seconds after which the trial is abandoned (result unknown).
~~~

### `ProgressBar` (`mediatools.core.progressbar`) {.unnumbered}

~~~text
Shows overall progress by bytes, files and estimated remaining time.

Progress is measured in source bytes, because encoding time grows with
file size far more than with file count. The remaining time is
``remaining bytes / speed``; the speed comes from this run once two
files are done or 30 s have passed, before that from earlier runs
(``initial_rate``).

Two lines are drawn: the overall progress (:meth:`line`) and the
current file (:meth:`file_line`: its percentage, size, encoded part and
remaining time). On a terminal both are redrawn in place and cut to the
terminal width, so they never wrap; otherwise (output redirected to a
file) nothing is drawn and only the log is written.

Attributes:
    total_bytes: Bytes of all files of the run.
    total_files: Number of files of the run.
    done_bytes: Bytes of finished files.
    done_files: Number of finished files.
    initial_rate: Bytes per second from earlier runs, or None.
    stream: Output stream.
    started: Start time (monotonic seconds).
    enabled: True if the stream is a terminal.
    note: Text shown at the start of the first line, e.g. a pending stop.
    drawn: True while the two lines are on the screen.
    status_path: If set, both lines are also written to this file (at
        most once per :attr:`STATUS_SECONDS`), for ``mediatools attach``.
    last_status: Monotonic time of the last status file update.
~~~

### `RunControl` (`mediatools.core.runcontrol`) {.unnumbered}


### `ShrinkDatabase` (`mediatools.shrink.database`) {.unnumbered}

~~~text
The shrink database file of one directory.

One database exists per directory that contains videos. A row means
"this file has been processed" - shrunk by ``mediatools shrink`` or an
earlier tool, or found to be HEVC already - regardless of the codec.

**Matching is by file name within the directory**, not by the stored
absolute path: the database describes the files of its own directory,
and the collection may have been moved or renamed since the row was
written (the stored path then still points to the old location). The
stored size is compared only to report rows whose file has changed
since (:meth:`status` returns ``changed``); such files still count as
processed, so nothing is encoded twice.

The file name is configurable (``[shrink] db_name``, default
``shrink.db``); ``mediatools rename-db`` renames databases created under
another name. Databases with an early schema (no PRIMARY KEY) are backed
up and migrated on first use.

Videos that could not be shrunk are kept apart in a second table, so
``files`` keeps its meaning ("processed") for every tool that reads it.
A failure counts only while the file has the recorded size; a changed
file is tried again. Older tools ignore the extra table.

Schema::

    CREATE TABLE files (path text NOT NULL PRIMARY KEY,
                        size integer, modified text)
    CREATE TABLE failures (name text NOT NULL PRIMARY KEY, size integer,
                           status text, reason text, at text)

Attributes:
    name: File name of the database.
    path: Absolute path of the database file.
    log: Optional logger.
    migrated_backup: Path of the backup made during a migration, if any.
~~~

### `HevcEncoder` (`mediatools.shrink.encoder`) {.unnumbered}

~~~text
Encodes a video with ffmpeg/libx265 and validates the result.

The output is accepted only if ffmpeg exits with 0, the file is not
empty, it is at least :attr:`MIN_RATIO` of the input's size, it contains
a video stream, its duration matches the input within
``max(TOL_ABS, duration * TOL_REL)`` seconds and - with a
:class:`DecodeCheck` set - the whole output decodes without a single
error (:meth:`DecodeCheck.verify`; time limit
``max(VERIFY_MIN, duration * VERIFY_FACTOR)``). A
suspiciously small output is typical of an input whose data could not
be decoded: the encoder then writes almost nothing but grey frames.

**CPU use.** libx265 runs its own thread pool, which by default uses
every logical CPU; ffmpeg's ``-threads`` does not limit it. Both the
decoder (``-threads``) and the x265 pool (``-x265-params pools=N``) are
therefore set to ``threads``, by default one less than the number of
logical CPUs, so that one CPU stays free. In addition ffmpeg runs with
the lowest CPU priority (``nice`` 19): it still uses every idle CPU,
but yields at once when the user works, so the desktop stays
responsive.

ffmpeg runs in its own session (process group): a Ctrl+C in the
terminal reaches only mediatools, which decides whether the current
encode finishes or is stopped with :meth:`abort`. Progress is read from
``-progress pipe:1``; ffmpeg's messages go to ``<dst>.ffmpeg.log``; the
file is deleted after a validated encode and kept otherwise (its last
lines are logged; the caller decides where it is kept).

Attributes:
    crf: libx265 constant rate factor.
    threads: Decoder threads and size of the x265 thread pool.
    niceness: Scheduling priority of ffmpeg (0 normal, 19 lowest).
    probe: :class:`MediaProbe` used for validation.
    log: Optional logger.
    decode: Trial decode of the output, or None (no decode check).
    ffmpeg: Name or path of the ffmpeg executable.
    process: Running ffmpeg process, if any.
    aborted: True after :meth:`abort` during the current encode.
~~~

**`__init__`**

~~~text
__init__(
    self,
    crf: int = 28,
    threads: int | None = None,
    probe: MediaProbe | None = None,
    logger=None,
    ffmpeg: str = 'ffmpeg',
    niceness: int = 19,
    decode: DecodeCheck | None = None,
)

Configure the encoder.

Args:
    crf: libx265 constant rate factor (28 is the libx265 default).
    threads: Decoder threads and x265 pool size; None uses
~~~

### `ReplaceJournal` (`mediatools.shrink.journal`) {.unnumbered}


### `Shrinker` (`mediatools.shrink.shrinker`) {.unnumbered}

~~~text
Shrinks the videos below a directory and keeps their file names.

A run has two phases:

1. **Plan** - :class:`ShrinkPlanner`: finish replacements interrupted
   by a crash, note leftover ``newShrinkedFiles/`` folders, collect the
   videos not yet recorded (and not recorded as failed, unless
   ``retry_failed``), drop short ones, set aside HEVC, sort.
2. **Encode** - per file: already HEVC -> record only; otherwise
   a trial decode (:class:`DecodeCheck`, if set) sets aside videos whose
   data cannot be decoded (status ``BROKEN``, never encoded, never
   recorded, original untouched);
   :class:`HevcEncoder` writes to ``newShrinkedFiles/``; only a validated
   result replaces the original (:class:`ReplaceJournal`: in place,
   crash-safe, the inode is kept, so ``_flat`` hard links see the new
   content) and is recorded. A file that fails (``FAILED``) or cannot be
   decoded (``BROKEN``) is recorded as failed in its directory's
   database and left out of later runs while its size is unchanged;
   ffmpeg's complete message file of a failed encode is kept in
   ``ffmpeg_logs``.

**Stopping.** The first Ctrl+C (or Ctrl+Z), or ``mediatools stop`` from
another terminal (see :class:`RunControl`), lets the current file finish
and then stops; the second Ctrl+C, SIGTERM or SIGHUP (terminal closed)
aborts the current encode at once - its partial output is deleted, the
original is untouched. Signals never interrupt the replacement itself.

**Crash safety.** See :class:`ReplaceJournal`.

**New release during a run.** ``mediatools reload`` (also sent by
``mediatools update``) asks the job to switch to the installed release.
Between two files - never during an encode or a replacement - the job
checks that the installed release starts (``--version``), closes its
table and summary and returns :attr:`RESTART`; the caller then replaces
the process (:class:`SelfRestart`). A release that does not start, or
the same version, is not switched to and the run continues.

**Leftovers.** ``newShrinkedFiles/`` folders that remain after recovery
hold only partial outputs of aborted runs. They are listed in the plan
summary and deleted only after the start question is confirmed.

With ``keep_copies=True`` the originals are not touched and nothing is
recorded; the shrunk copies stay in ``newShrinkedFiles/`` for review.

Attributes:
    root: Absolute start directory.
    log: Logger.
    opts: What is processed and how (:class:`ShrinkOptions`).
    encoder: Encoder for new files.
    state: Persistent helpers: ``durations`` (for ``min_seconds``) and
        ``codecs`` (HEVC check of the plan) - None probes without caching -
        ``throughput`` (speed and size ratio for the estimates) and
        ``decode`` (trial decode before encoding; None skips it) and
        ``ffmpeg_logs`` (folder for the ffmpeg messages of failed
        encodes; None deletes them) and ``restart`` (switch to a new
        release on request; None ignores requests).
    planner: Planning phase; holds the probe and the replacement
        journal.
    control: Stop requests from ``mediatools stop``, or None.
    databases: Open databases per directory.
    flags: ``stop`` (finish the current file, then stop), ``abort``
        (stop the current file at once) and ``restart`` (switch to the
        installed release before the next file).
    display: Progress display of the encode phase.
    stats: Counters ``shrunk``, ``hevc``, ``skipped``, ``short``,
        ``failed``, ``broken``, ``failed_before`` (left out: recorded as
        failed), ``regrown`` (recorded, but larger again: planned),
        ``copies``, ``recovered``.
    found: ``failed`` - paths that could not be encoded; ``broken`` -
        paths whose data could not be decoded; ``failed_before`` - paths
        left out as recorded failures; ``leftovers`` -
        ``(folder, files, bytes)`` of leftover work folders; ``hevc`` -
        ``(path, size)`` of planned videos that are already HEVC.
~~~

~~~text
====== ==========================================================
Level  Rule
====== ==========================================================
0      full path, ``__`` separated
1      configured folder names abbreviated, ``<id> <date> <time>``
       folders compacted to ``<id>-<YYYYMMDD>T<hhmmss>``
2      level 1 plus the front of the file stem cut; the tail
       (usually the media id) is kept, ``~`` marks the cut
3      directory part replaced by an 8-digit hash, file stem cut
====== ==========================================================

The exact origin of every link is always recorded in ``_index.tsv``,
so even level 3 names stay traceable.

Attributes:
    limit: Maximum name length in bytes.
    abbrev: Folder name abbreviations used from level 1 on.
~~~

### `SyncProbe` (`mediatools.snapshot.syncprobe`) {.unnumbered}

~~~text
Compares the source with a mirror without changing anything.

The dry run uses the same rsync options as rsnapshot (``-aH --delete
--no-inc-recursive`` plus the excludes) and reports what a real sync
would do. It answers the two questions that decide whether a run is
safe: *is this mirror really a copy of this source?* (transfer volume)
and *how much would disappear from it?* (deletions).

Attributes:
    settings: Validated settings.
    rsync: rsync executable.
~~~

~~~text
__init__(self, settings: SnapshotSettings, rsync: str = 'rsync')

    rsync: rsync executable.
~~~

~~~text
    Argument list.
~~~



**`looks_like_copy`**

~~~text
looks_like_copy(result: dict[str, Any], tolerance: float = 0.25) -> bool

Tell whether the mirror is plausibly a copy of the source.

If more than ``tolerance`` of the source volume would have to be
transferred, the mirror is most likely a different directory (wrong
path or wrong level) and must not be adopted.

Args:
    result: Result of :meth:`run`.
    tolerance: Accepted share of data to transfer.

Returns:
    True if the transfer volume is within the tolerance.
~~~

### `SystemdTrigger` (`mediatools.snapshot.trigger`) {.unnumbered}

~~~text
Creates ``~/.config/systemd/user/mediatools-snapshot.service``.

The service is ``WantedBy`` the mount unit of the backup disk, so the
user's systemd instance starts it whenever the desktop mounts the disk.
Mount units of all mounted file systems are visible to the user
instance; :meth:`mount_unit_known` verifies that for the actual disk
before anything is installed. The run uses ``-y``: it never asks, and it
aborts instead if the deletion limit would be exceeded.
~~~
